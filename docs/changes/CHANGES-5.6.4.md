# 淨頁 Clearview 5.6.4

這一版先量測，再只改量得出效果的地方。

## 量測結果
12 個真實網站（台灣、中國、英文新聞與影音）裝上擴充功能後：每頁 1,300 到 5,300 個元素，平均 1.6 個子框架。
以這個形狀做的本機測試頁（約 3,000 個元素、2 個子框架），25 次載入的中位數：

| | 沒裝 | 5.6.3 |
|---|---:|---:|
| 請求開始 | 2.3 ms | 3.2 ms |
| DOM 可互動 | 15.0 ms | 約 21 ms |
| load | 約 31 ms | 約 41 ms |

多出的約 6 毫秒裡，共用樣式表（13,000 多個選擇器）的解析與建立規則集約 3 毫秒，內容腳本約 2.5 毫秒，
請求階段約 1 毫秒。把內容腳本延到頁面閒置時才執行只省 1 到 2 毫秒，卻要改寫樣式套用的整個流程，
風險不成比例，所以沒有做。頁面端已經接近這種做法的下限。

背景程式每次被喚醒後處理一個頁面約 4 毫秒，其中最大的一項是 510 KB 的修正索引。

## 改動
- **修正索引改成二進位**（`data/engine/fix-keys.bin`，由 `tools/fix-index.mjs` 產生）：內容是排序過的 32 位元雜湊，
  不必解析 JSON。索引載入 4.9 ms → 1.2 ms；背景程式載入全部資料後的記憶體 4,981 KB → 3,560 KB；
  套件少約 400 KB。`tools/test-fix-index.mjs` 確認 24,583 個鍵都對應到原本的資料檔。
- 測試讀取修正資料檔的方式改為直接執行檔案，不再用容易誤切的正規表示式。
