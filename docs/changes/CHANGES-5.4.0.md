# 淨頁 Clearview 5.4.0：引擎重寫

從底層改了元素隱藏、網站修正和背景流程，攔截的內容不變，負擔大幅下降。

本機測試頁（4000 個元素，Chrome）：

| 指標 | 5.3.1 | 5.4.0 | 沒裝擴充功能 |
|---|---:|---:|---:|
| 首次繪製 | 84 ms | 48 ms | 44 ms |
| 廣告被隱藏的時間 | 49 ms | 14 ms | — |
| 頁面主執行緒耗時 | 96 ms | 59 ms | — |
| 頁面記憶體 | 10.3 MB | 1.7 MB | — |
| 含 6 個 iframe 的頁面耗時 | 154 ms | 64 ms | — |
| 頁面靜置 30 秒的腳本時間 | 355 ms | 73 ms | — |
| 背景記憶體 | 14–34 MB | 3 MB | — |
| 靜態規則數（全部清單） | 132,365 | 31,260 | — |

## 改了什麼
- **網站修正腳本不再每頁載入**：3.2 MB 的 `advanced-main.js` 拆成函式庫和 32 個資料檔，只在需要修正的網站載入。網站是第一次造訪時登記的，登記後都在頁面腳本之前執行。
- **通用元素隱藏改成靜態 CSS**：由瀏覽器在頁面開始時直接注入，不再從 storage 讀 600 KB 進每個頁面。
- **網站專屬規則改成分片索引**：背景不再解析 8 MB 的 JSON、也不再逐條比對，只讀這個網址對應的小檔案。
- **Service worker 喚醒不再重做一切**：以前每次喚醒（包含每 4 分鐘的統計）都會重寫所有規則與腳本，並對所有分頁注入腳本。現在只有設定真的改變才做。
- **頁面請求不再互相排隊**：每個分頁各自排隊，一個 frame 慢不會拖累其他分頁。
- **靜態規則合併**：相同語意的規則併成一條，Chrome 也和 Firefox 一樣受益。
- **元素選取器按需載入**，靜置頁面的 Shadow DOM 掃描從每 1.5 秒退避到每 30 秒，頁面有變動時立刻恢復。

## 行為上的差異
- 暫停網站、相容模式、總開關：從面板操作時會自動重新整理分頁；從設定頁改的話，要重新整理才看得到通用隱藏的變化。
- 第一次造訪需要修正的網站時，如果是剛開的新分頁，腳本可能比頁面晚一點執行；第二次起就會準時。
- 通用隱藏的 CSS 優先權變成頁面層級；網站專屬規則維持最高優先權。
