# Ad Shield 4.8.0 — 恢復正常跳轉與登入

日期：2026-10-22

這版針對郵件連結無反應、正常新分頁被關閉、Google 登入跳轉失敗，調整預設行為與過濾例外。前版局部修補未解決使用者實際問題；本版已完成本機情境驗證，尚未在使用者的 Gmail 或實際 Google 帳戶驗證。

## 改動

- 一般模式改用瀏覽器原生開窗、連結與表單行為，不再覆寫 `window.open` 或表單提交。嚴格模式改為手動選項，仍可能影響登入、付款或下載流程。
- 網頁頂層導覽可通過廣告清單；不因此放行目的網頁的廣告資源。使用者手動封鎖網域仍有效，手動允許優先於手動封鎖。
- Google Identity / OAuth 的 `accounts.google.com` 與 `oauth2.googleapis.com` 加入必要服務例外；不包含 ping，也不放行整個 google.com。
- 相容模式停止自動隱藏與網站修正腳本，恢復該網站第一方資源，保留主要第三方廣告網路過濾與手動隱藏規則。
- 「套用加強攔截模式」保留核心廣告清單及版面過濾，不再自動打開嚴格防彈窗、17 項服務限制、額外網域追蹤限制、直接拒絕模式及干擾清單。
- 保留 Apple 風格介面，更新設定說明。網路清單快照及擴充功能權限未變。

## 升級會自動修正舊設定

首次執行 4.8.0 將全域及個別網站的嚴格防彈窗改為一般，關閉額外追蹤、17 項服務限制、直接拒絕及干擾清單。原有白名單、相容網站、手動允許／封鎖、手動隱藏和全域暫停狀態保留。原設定備份在此擴充功能本機儲存的 `navigationSettingsBackup`，不會上傳；升級標記為 `navigationCompatibilityVersion: 2`。之後手動選擇的設定不會在每次啟動被重置。

這項調整優先恢復網站功能，可能降低某些連線測試分數，也不再由一般模式清理網站自行開出的視窗。第三方廣告資源仍接受核心清單過濾。請勿為追求測試分數立即重新開啟全部進階限制。

## 安裝與重新載入

1. 解壓縮 `ad-shield-v4.8.0.zip`。若要保留舊版設定，將內部 `ad-shield` 的檔案更新到 Chrome 原先載入的擴充功能資料夾，再於 Chrome 擴充功能管理頁按該項目的重新載入。
2. 也可停用舊版，選「載入未封裝項目」並選取新版包含 `manifest.json` 的資料夾。不同資料夾可能產生不同擴充功能 ID，設定不一定沿用；不要同時啟用舊版。
3. 打開面板確認 **4.8.0**。如果先前曾全域暫停，請自行恢復總開關。
4. **重新整理 Gmail 與登入來源頁面，或關閉後重新開啟。** 已存在頁面的舊腳本不會因更新檔案而自動消失。先前暫停的單站仍保留，需測試該站攔截時再恢復。
5. 再試郵件連結及「使用 Google 登入」。一般模式是建議預設；若個別網站仍異常，使用單站相容模式並重新整理。

## 驗證方法與限制

使用獨立 Chrome 測試設定檔與本機 HTTP/HTTPS 測試頁，不使用日常瀏覽器設定檔、郵件內文或登入憑證。

- 導覽專項：登入按鈕、延遲開窗、空白視窗中轉、委派連結點擊、跨視窗表單、直接導覽、Google 服務規則、手動名單優先序、相容模式、一次性升級與備份。
- 廣告回歸：原生網路規則、替代資源、動態隱藏、元件內廣告、明確選用的嚴格模式、設定交易與介面操作。
- 介面：面板狀態、開關、相容模式、加強按鈕及桌面／手機寬度設定頁。

原始結果保存在 `verification/v4.8.0/`。重現工具：`node tools/test-navigation.mjs`、`node tools/test-browser.mjs`、`node tools/preview-ui.mjs`（需要 macOS Chrome、Node.js；導覽測試也需要 openssl）。Google 主機名稱在導覽測試中指向本機假資料，不是真實 Google 登入；通過本機測試不代表所有實際帳戶流程已確認正常。嚴格模式內另包含先前未發佈的 4.7.2 同目的連結委派修補。
