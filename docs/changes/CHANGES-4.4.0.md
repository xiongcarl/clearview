# 清靜瀏覽 · Ad Shield 4.4.0

以你提供的 4.3.1 原始碼修改，重點是修復漏攔與誤攔的具體原因。ZIP 內含可載入的插件、完整原始碼、規則來源、測試工具及結果。

## 這次修改

- **恢復失效的廣告選擇器**：原本會把合法的 `^=` 屬性前綴比對，以及引號內含 `;`、`@` 的屬性值當成不支援而略過。新版保留這些規則，仍拒絕引號外的 CSS 宣告／規則注入字元、不完整引號及畸形括號。
- **修正過濾引擎分工**：巢狀 `:has()`、文字和樣式比對規則交給既有程序式引擎；不把瀏覽器不支援的指令當成原生 CSS。原生選擇器共 76,631 個不重複項目，全部通過本次 Chrome 語法驗證。
- **讓網站例外真正生效**：`generichide/ghide`、`elemhide/ehide`、`specifichide/shide` 現在統一作用於啟用的清單、內建隱藏規則及元件樣式；全域元素隱藏例外也會約束自動程序式過濾。個別選擇器例外可跨清單與引擎生效。
- **避免錯誤放行**：支援完整相同的隱藏例外 `$badfilter` 取消；修正清單關閉時，取消也會停止。保留網域範圍、排除子網域及 entity 規則。不支援的路徑／其他條件不會擴大成整站放行。
- **降低本地補充網路規則的誤攔**：補充廣告路徑規則的優先權從 1800 調為 90，低於上游轉換規則的最低 100，讓精確的相容性放行能生效。沒有例外時仍攔截，手動封鎖／允許仍保留優先權。
- **保留可維護性**：新增共用化的 cosmetic 編譯器與離線重建工具；完整清單更新流程使用同一套邏輯。保留原版權限、網路清單快照、腳本修復引擎、彈窗預設和使用者設定格式。

## 實測結果

於 macOS 的 Chrome 155.0.8059.80，以隔離設定檔和本機 HTTP 伺服器測試，未使用你的日常瀏覽器資料。相同測試頁面以主機名稱映射到本機，並未把這些結果當成真實網站實測。

| 檢查 | 結果 |
| --- | --- |
| 既有完整 Chrome 回歸套件 | 224 / 224 通過 |
| 新增編譯器及例外政策測試 | 45 / 45 通過 |
| 新增瀏覽器行為對照案例 | 4.3.1：13 / 34；4.4.0：34 / 34 |
| 原生 CSS 語法驗證 | 新版 76,631 個不重複選擇器全部通過 |
| 既有網路 `$badfilter` 編譯測試 | 11 / 11 通過 |
| 完整離線清單重建 | 通過，使用鎖定依賴版本 |

34 項對照案例涵蓋屬性前綴與樣式廣告、中文清單、封閉 Shadow DOM、正常鄰近內容、跨清單／內建樣式例外、巢狀 `:has()`、暫停後恢復，以及相容性放行優先權。這些是針對已知缺陷設計的案例，**13/34 與 34/34 不是廣告攔截率**。

本次 Chrome 能解析的不重複原生隱藏選擇器由原版的 72,970 個增至 76,631 個，增加 3,661 個。這是語法支援與規則覆蓋的證據，不能直接換算成真實網站攔截率或誤攔率。

## 安裝／更新

1. 解壓縮 ZIP，找到內含 `manifest.json` 的 `ad-shield` 資料夾。
2. 如果原版是以「載入未封裝項目」安裝，先備份原插件資料夾，再把新版檔案覆蓋到**同一個資料夾**。到 `chrome://extensions` 按該插件的重新載入，通常可沿用既有設定；不要先移除插件。
3. 如果是首次安裝，在 `chrome://extensions` 開啟開發人員模式，按「載入未封裝項目」，選取解壓後的 `ad-shield` 資料夾。另一路徑可能得到不同的插件 ID 與獨立設定。
4. 重新整理已開啟的網頁，讓既有注入腳本及樣式換成新版。不要同時啟用新舊兩份。

此次只交付檔案，沒有更動你日常 Chrome 中已安裝的插件。

## 驗證範圍與限制

- 改善重點是規則解析、廣告元素隱藏與例外精準度；本版沒有重新下載上游網路清單，也沒有宣稱 YouTube 影片內廣告等情境已解決。
- 尚未進行大量真實網站、登入／付款流程或其他作業系統的回歸測試，因此不能承諾所有網站的廣告攔截率提升多少，或完全沒有誤攔。
- 路徑限定的元素隱藏例外，以及 `:matches-path()`、HTML 過濾和某些屬性修改指令等仍不支援；建置統計保留略過數量，程序式引擎會再驗證可用選擇器。
- 預設仍是原版的嚴格防彈窗模式。特定網站的登入或付款按鈕若受影響，可改用該站的一般模式並重新整理。

## 開發依賴檢查

沿用原專案的鎖定版本。`npm audit` 回報 6 項建置依賴警告（5 項中度、1 項高度），涉及 `js-yaml`、`sprintf-js` 及依賴鏈；完整結果附於 `verification/v4.4.0/dependency-audit.json`。安裝包不含 `node_modules`，這些模組不會作為模組載入到插件執行環境。本次沒有把建置依賴升級混入攔截行為修改；後續開發仍應評估升級及重建相容性。

## 重現與原始結果

在解壓後的插件資料夾內，使用 Node.js 執行：

```sh
node tools/test-cosmetic-policy.mjs
node tools/test-cosmetic-browser.mjs
node tools/test-browser.mjs
node tools/build-cosmetics.mjs
```

瀏覽器測試預設使用 macOS 的 `/Applications/Google Chrome.app`；新對照工具可透過 `AD_SHIELD_CHROME` 指定測試瀏覽器路徑。完整重建先在 `tools` 執行 `npm ci --ignore-scripts`，再於插件根目錄執行 `node tools/update-web-lists.mjs --offline --dry-run`。

本次結果保存在 `verification/v4.4.0/`。原有其他驗證檔與文件中的舊版章節屬歷史記錄。

實作核對來源：[uBlock 靜態規則語法](https://github.com/gorhill/uBlock/wiki/Static-filter-syntax)、[Chrome declarativeNetRequest 優先權說明](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)。
